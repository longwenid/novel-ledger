# 累计快照存储修复 · 2026-10-20

已修复上一轮发现的累计完整快照存储膨胀。在相同 1,667 章、至少 5,001,000 合成汉字夹具中，数据库从 1,927,741,440 字节降至 50,847,744 字节，减少 **97.36%**。旧冻结来源完整保留，基线与修复版全部 3,334 个完整来源的哈希一致。前次报告的未修复项由本记录闭合，历史测量不改写。

本轮在原有未提交质检修改之上继续修复。所有小说项目均为自动清理的临时夹具，没有修改真实小说项目、调用写作模型或迁移旧数据库。

## 修复内容

- 存储适配器把大型 dict/list 保存为不可变内容寻址块。嵌套累计数组与字典也共享，列表使用固定叶和分层清单，字典使用稳定哈希分桶；追加版本不形成越来越长的历史增量链。
- `document(value)` 仍返回完整逻辑值的哈希，`read_document(hash)` 仍返回完整普通值。每次读取核对全部所需块与最终逻辑哈希，不通过跨调用缓存跳过核验；相同子树不会在返回值中引入可变别名。
- 所有旧冻结任务仍引用原来的完整状态与理解版本，正文、事实及证据不截断。底层专用编码与任意用户 JSON 值分离，清理时跟踪文档及共享块的完整引用闭包。
- 独立 document/save/history_snapshot 原子发布，有外层事务时复用。清理共用写事务，先验证所有可达来源，后删除；损坏、缺块或删除中途故障均保留原记录，回滚已经删除的根与块。清理提交后再回收文件空间。
- 只读诊断工具改为重建逻辑来源，不把物理清单长度误报为模型上下文量。

存储协议升为 **novel-ledger/5**，逻辑作品根仍为 novel-ledger.book/1。当前引擎明确拒绝 /4 及更早库并保持原文件不变，不自动迁移；本轮没有修改开书、正文回执或作者授权协议。

## 成本与适用边界

共享磁盘的代价已实测：1,667 章生成 CPU 从 73.659 秒增至 118.512 秒（1.61 倍），最新两份完整来源读取中位数从 12.341 ms 增至 23.752 ms（1.92 倍）。完整逻辑序列化、哈希、领域组装与读取仍处理完整值，CPU 没有因物理共享变为常数成本。

显式清理需要完整验证所有留存版本：本次 CPU 从 12.876 秒增至 18.234 秒，持有写锁；即使二次清理没有可删除内容，也仍支付核验成本。它不是每章自动调用的步骤。任务表和派工文件另按任务留档，本轮没有删除这部分审计记录。

该修复解决已复现的累计快照磁盘问题。大范围修改旧内容可能降低共享率；真实长篇文学效果、模型会话隔离及计费用量仍是独立验收范围，不以本次合成工程通过宣称剧情语义永不漂移。
