## 1. 接口与字段

### 1.1 声明常量（drift.py）
```python
VOLUME_FIELDS   # += 'hooks', 'style'
CHAPTER_FIELDS  # += 'hooks', 'style'
HOOK_ACTIONS = ('plant', 'payoff')          # 只有两个动作；中途再提用既有 hook_refs
HOOK_FIELDS  = ('id', 'text', 'plant', 'payoff', 'required', 'continues')
ITEM_KINDS      # += 'hook'（drift_check 自比行）
```
- 卷纲行：`hooks: [{id, text, plant:[最早,最迟], payoff:[最早,最迟], required, continues}]`，**必填**（可空数组）。
- 章纲行：`hooks: [{hook, action: plant|payoff, note?}]`，**必填**（可空数组）。
- `plan_rows` 额外带出 `hooks`（章行原样）与 `hook_contracts`（本章动作涉及的卷纲声明：text/payoff 窗口），形状同 `node_contracts`。
- `story_memory.reads` 增读 `plan['hooks']` 的 hook 坐标（见 §6 越界说明）。

### 1.2 卷纲校验（`validate_volume_outline`，criterion `volume_hook`）
1. `hooks` 必须是数组（缺字段报错：空数组才是"本卷没有伏笔"的声明）。
2. 行形状：`id/text` 非空、`plant/payoff` 为两章区间、`required` 为布尔、`continues` 为布尔（可省，缺省 false）。
3. **命名空间**：`id` 与节点/线路/伏笔共用一套命名；覆盖既有 id 须 `continues:true`，本卷内重复声明无论是否 continues 都拒。
4. `plant` 窗口必须落在本卷 `[first,end]` 内。
5. `payoff[0] >= plant[1]`。
6. `payoff[1] > 本卷 end` ⇒ 必须 `continues:true` **且** `required:false`（跨卷伏笔）；`required` + 越卷 = 非法。

### 1.3 章纲校验（`validate_chapter_outline`，criterion `chapter_hook`）
1. hook 注册表 =「本卷卷纲声明的 id」∪「`state0['hooks']` 中 `status=='open'` 的既有 id（前卷遗留未兑现）」。
2. 同一 id：`plant` 恰一次、`payoff` 恰一次；`payoff` 必须晚于 `plant`（同章允许，按声明顺序判定）。
3. `plant` 落在 plant 窗口内；`payoff` 落在 payoff 窗口内（承接前卷、本卷未声明的 hook 无窗口可查，其**期限由 `due` 经 `facts` 的 `hook_due` 兜底**）。
4. `hook_refs` 中每个 id 必须已埋（本卷更早章已 plant，或 `state0` 中已存在）。
5. 两处独立判定、同一 criterion：校验期语义遍历 + `simulate` 状态机（后者保证任何入口都拦得住）。

### 1.4 卷内状态链与卷末闭合
- `simulate` 维护 `state['hooks']`：`plant → {'status':'open','due':payoff[1],'text':…}`；`payoff → 'paid'`；重复 plant / 重复 payoff / payoff 早于 plant / 越窗都在此处再判一次（criterion `chapter_hook`）。
- **hooks 不进 enter/exit 坐标**（spec §1.2 未列，且 enter/exit 的 kind 白名单不含 hook）：退出坐标算术把它们排除，承诺账由状态机跟踪。
- `_closure`（卷末，criterion `drift_closure`）：本卷 `required:true` 的每个 hook 必须 `paid`；`continues:true` 允许仍 `open` 并带入下一卷。
- `state_mismatch` 增判 hook：按**章内声明顺序**推演（plant 期望当前无该 hook，payoff 期望 `open`），同章 plant→payoff 不会误判成漂移。

### 1.5 结算事件（`reconcile`，复用 `facts.settle` 的 `hook` op）
| 动作 | 事件 |
|---|---|
| plant | `{'op':'hook','id','status':'open','due':payoff[1],'text':…,'before':None,'reason':note,'evidence':…}` |
| payoff | `{'op':'hook','id','status':'paid','before':'open','reason':note或默认,'evidence':…}` |
- `due`/`text` 由引擎从卷纲声明（`hook_contracts`）取，写手只填 `planned/actual = {'action': …}` 与正文引文；前态 `before` 由引擎投影（写手不填）。
- 自比覆盖：每个章纲 hook 动作一条 item；漏项 `drift_coverage`、kept 但动作不符 `drift_kept`、缺 action `drift_actual`、无正文引文 `drift_evidence`、事件构造失败 `drift_hook`。事件顺序按章纲声明顺序，同章 plant→payoff 时 plant 先结算。

## 5. 修复跟进（tests-a 报的三条真实缺陷，已修好并复验）

1. **修复批次的前缀被误判**（`test_outlines::test_a_repair_batch_anchors_on_the_state_the_book_is_actually_in`）：形状阶段的 hook 语义校验拿 `state0` 判"是否已埋"，而 repair 回执会重提前缀章 → 前缀里已结算的 plant 被判"plant 两次"。修法：把锚点计算提到形状阶段之前（新增 `_anchor(...)`），**锚点之前的行视为历史、跳过 hook 语义校验**（`_deltas` 的形状校验仍对全部行执行）；锚点语义与原实现一致（`from_chapter` 优先，否则取"首个 enter 与真实状态相符"的章）。
2. **coverage 去重键不支持同章 plant→payoff**（`test_pipeline_shapes::test_no_tier_dispatches_any_deleted_review_stage`，t2 的 1 章卷）：coverage 以 `(kind,key)` 为唯一键，把同一承诺的埋设与兑现两行合并 → `drift_coverage` + `drift_kept`。修法：新增 `_coverage_key(kind,key,planned)`，hook 行身份是 **`(kind,key,action)`**（action 取自该行的 `planned.action`，缺失时给出专门的可读报错）；clock 仍归一为 `('clock','clock')`，其余 kind 不变。
3. **reconcile 的投影影子把动作当成状态**：`_shadow_apply` 对 hook 存的是 `actual.action`（`'plant'`），同章 payoff 因此看到 `status=='plant'` → `drift_hook`，修复退回死循环。修法：新增 `HOOK_STATUS = {'plant':'open','payoff':'paid'}`，影子按**结算后的状态**推进；事件顺序保持声明顺序（plant 在前）。

复验：自测 §2b/§3b 专测同章短钩（校验、`state_mismatch`、链、reconcile 两行 coverage、事件顺序、`facts.settle` 后 paid/open）；`pytest tests/test_narrative.py tests/test_outlines.py tests/test_longform.py tests/test_pipeline_shapes.py tests/test_domain_boundaries.py tests/test_architecture.py -q` → **134 passed, 313 subtests passed**。
