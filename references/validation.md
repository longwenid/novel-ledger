# 验证

当前执行仅以本技能入口、[任务协议](protocol.md)、[运行流程](runtime.md) 及其专项指南为准。`validation/` 中的历史规格、实验和报告只保存当轮证据，不作为执行规范或兼容承诺。

何时读：修改引擎、检查协议与材料成本，或设计真实长篇的文学及用量验收。

## 验证范围与结论依据

| 范围 | 使用的证据 | 能支持的结论 |
|---|---|---|
| 工程行为 | 临时新项目、合成回执、真实子进程、行为及依赖测试 | 提交、回滚、权限、版本与恢复符合协议 |
| 章纲与漂移 | 状态链模拟夹具、人为漂移样例、drift_check 漏项样例 | 设计期能否挡住资源/位置/知情漂移，执笔核算是否覆盖完整 |
| 材料与存储 | 冻结记录字节、目录页、来源哈希、读取观测 | 来源保真、复用和读取量；字节不能直接换算计费 |
| 文学效果 | 连续完整正文、真实卷界、人工抽读与离线盲测工具 | 人物、因果、节奏和兑现的具体得失（**v2 引擎不再自动产出这类判断**） |
| 宿主与费用 | 真实子 agent 会话、派工与提交记录、token/缓存及账单日志 | 模型历史隔离、子 agent 执行与真实费用 |

工程夹具不调用付费模型，明确标记为合成材料。语义判断沿 [创作与自比](craft.md) 的原文、问题、影响与处理范围进行，不用字段通过率、节点数量或源码行数替代文学质量。

## 工程检查

日常默认运行 `python3 validation/run_tests.py`（快速组）；先按下表选择受影响的行为回归。跨模块规则、持久化结构或公共协议的广泛变更使用全量测试；依赖、材料选择或历史传输变化时另做度量。仅调整文档时，核对链接、示例和相关图源；若改写了操作流程，再运行对应行为回归。

在技能仓库根目录执行，按本次改动选用：

```bash
python3 validation/run_tests.py fast
python3 validation/run_tests.py full
python -m pytest tests/ -n auto          # 全量并行（装 pytest-xdist；用例各建临时项目，可安全并行）
python3 <skill-creator>/scripts/quick_validate.py ROOT
python3 validation/measure.py --out /path/to/metrics.json
```

`fast` 固定覆盖架构、端口替换、角色隔离、有限预算、修订授权及端到端交付（含档位形状声明、章纲状态链与漂移核算的守卫）；`full` 自动发现 tests/ 中全部测试。两种入口均在失败时返回非零状态，可供本机或 CI 调用；`--list` 仅列出案例，`-v` 显示逐项结果。安装 pytest-xdist 时可使用并行入口；测试数量与耗时以当前执行结果为准，历史版本的测量不作为当前预算。新增关键边界时维护快速组，新增测试始终由完整组自动收集。快速检查通过后，跨模块重构仍须完整回归；原 unittest discovery 命令继续可用。

`validation/anchor_check.py` 核对根目录、references/ 与 docs/ 活跃 Markdown 的行内本地文件链接、同页与跨页精确标题锚点；跳过围栏代码示例，坏引用返回非零。历史 validation/ 报告、引用式链接和 Setext 标题不在此入口覆盖内（改标题或挪小节后运行）。quick_validate 属宿主自带工具，路径按本机实际安装替换；它是可选的附加校验，缺失时不影响上面的测试与测量。Windows 控制台默认 GBK：测试与 CLI 自身按 UTF-8 读写，但外部校验脚本可能仍按本地编码读文件，此时对全部命令加 `PYTHONUTF8=1`。

表中的入口是定位起点，按实际调用关系补充关联回归；核验要求分别维护于 [运行](runtime.md)、[协议](protocol.md)、[叙事推进](narrative.md) 和 [编辑能力](editorial.md)。新增或改写后的用例名以 `tests/` 实际内容为准。验证观察提交、拒绝、保留、恢复和交付等结果，避免只匹配文档措辞或实现细节。真实模型历史隔离仍需宿主另验收。

例如只改自动回改逻辑时，可先运行：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_revision_bounds.py' -v
```

文档检查重点包括等待与 --after、accepted 与正文通过的区别、超界方案落盘及授权入口。图表依赖未变时核对派生源码一致性即可；历史验收保留原条件，新增检查另行留档。

## 技能指令与路由验收

修改技能入口或专项指南时，先检查 frontmatter、UI 元信息、本地链接与锚点、表格和命令示例，再按下列场景核对读取顺序及实际行为。优先复用隔离临时项目中的现有行为测试，不为表格措辞添加断言。

| 代表请求或状态 | 应读入口 | 应观察到的行为 |
|---|---|---|
| “没有想法，帮我开一本书” | [逐门开书](opening.md#入口选择) | 从第一门开始，提交方案后等待作者，不自行选择或开始正文。 |
| “题材和书名已定，继续补齐” | [逐门开书](opening.md#入口选择) | 合法部分选择经 intake 登记；不重问已有决定，不绕过已展示门板。 |
| “继续这个已有项目” | [运行与恢复](runtime.md#主干循环默认执行路径) | 恢复同一任务及作者目标；有效认领等待，不重复派工。 |
| “写这一卷的章纲” | [叙事推进](narrative.md#章纲)、当前冻结任务 | 按卷纲登记节点/线路与真实前态算清增量，填 enter/exit；状态链拒绝即按 `design_drift` 返修，不绕过。 |
| “这一章的资源/位置对不上” | [叙事推进](narrative.md#执笔自比与引擎核算) | 先看引擎给的投影前态；漏项或前态不符被拒不重交原样候选，偏差如实诊断并返修本章正文，不能自动修改固定章纲。 |
| “改旧章”或回改超界 | [修订影响分析](runtime.md#修订影响分析) | 先分析事实与阅读影响；保护正式稿，超界绑定准确方案授权。 |
| “交付已完成的内容” | [运行与恢复](runtime.md#阶段结束与交付) | 区分实际覆盖与全书；完本先验收，导出失败只重试准确快照交付。 |
| “优化这个 skill”或仅讨论架构 | [架构](architecture.md)、本页 | 修改或分析技能工程，不创建小说项目或派创作任务。 |

上述工程测试验证引擎能否执行这些边界，不能证明模型一定会选对指南，也不证明写出来的小说好看。验证技能实际使用时，另记录代表请求、实际读取的参考文件、行动及结果；若调用独立使用者，应只给请求与待验技能，避免把预期路线当成答案注入。没有完成这类试用时如实注明，不将元信息检查等同于模型行为验收。

## 材料与历史度量

记录模块、完整依赖图和必读完整记录字节。增加未引用未来节点时，必读材料不应无故增长，全设计仍可按哈希补读；连续依赖链与 20/100/500 章历史另测，保留完整来源。

history_transport 使用独立存储夹具，500 章包含至少 150 万合成汉字。记录目录入口、原全量摘要/事件索引字节、首次构建与复用、实际事件页读取、无命中最坏扫描和最早章完整补读。行为测试覆盖损坏、冻结边界、分支共享前缀、承诺关联、原事件解释及补读量留痕；存储夹具不构成完本交付。

数百万字体量另用 `python3 validation/longform_stress.py --out /path/to/longform-stress.json`：默认测 100/500/1000/2000 章、每章至少 3000 合成汉字的末章必读、主控派工、冻结补读与重开保真，并独立跑 100 章/10 卷的真实工程提交和完本链。前者是来源记录，后者使用短合成正文，两者都不是实际百万字文学写作。相同任务增加 20/100/500/2000 条已收束伏笔和线路时，必读材料不应增长，完整旧来源与显式旧依赖仍须可读，见 test_context_growth。

正文历史不能代表全部存储成本。用 `python3 validation/storage_snapshot_probe.py --sizes 100,500 --out /path/to/storage-snapshots.json` 单独量化累计人物发展和理解版本；更大规模显式指定 1667 等章数。存储协议 /5 对嵌套累计集合共享未变块，冻结来源仍为完整逻辑快照。报告当前逻辑值字节、文档根及共享块的物理总字节、数据库字节、生成与完整读取耗时、重开及清理效果，验证每个旧冻结来源仍可按原哈希完整读取；不把块清单大小当上下文量，也不把磁盘减少推断为序列化/核验 CPU 恒定。

对照架构或流程时固定相同创作输入、模型和来源，计入首次正文前规划量、后续补纲/重排、修订范围、实际读取量及新增场景材料。测量结果按条件报告，不将任务减少或分区拆分直接等同于全程收益。

真实长篇文学对照尚未完成，试写按下一节先做连续数十章预验收，再验证远距离回归与授权长篇目标。

## 真实长篇验收

在作者授权的独立小说项目中固定模型、题材、篇幅、条件和验证档位，保存引擎版本、作者约定及准确交付快照。百万字目标须实际写至授权终点并通过 complete/deliver；短篇试跑只算预验收。验收分别记录：

- 连续性：人物/物品再次出现时的远期承诺、跨卷因果和揭示，抽检原文与事实事件是否一致；启用连续性保障时由独立读者在原文上核验，仍须记录其准确版本与宿主可信性；关闭或缺失报告时由作者或外部评测完成，不能称已自动证明。
- 多线与呼吸：人工盲读连续完整章节及真实卷界，检查主线是否可感、支线的作用、暗线线索与揭示、高潮余波和静章变化；用原文说明得失，不以固定推进间隔、角色标签或张力分数当金标准。
- 效率：分别保存派工/补读字符量、宿主实际 token/缓存日志、失败调用、返修次数及人工干预；对照版本应固定相同来源和模型条件。没有计费日志则费用未知，不从字节换算费用。

人物对白样本库、主线间隔提醒与其他节奏辅助先在同条件盲评中验证收益及误报，再决定是否引入；不把尚未证实的建议直接变成拒绝规则。判据前移的收益须记录实际派工数与漂移检出的阶段，并在同条件评测中验证，但**不能把派工数下降说成文学质量提升**——那部分判断必须来自实际独立阅读，而非工程派工次数。

调整文风指引可先做隔离小样：固定同一场景事实与作者风格，由空历史写手分别使用冻结的前后指引，独立读者只收匿名正文与场景要求，给出精确引文和可有可无的偏好。允许无显著差别，不用“AI味分数”、禁词命中或数值接近首章替代阅读。一两组模型小样不证明长期文学收益；角色视角与事实仍要结合原文检查。此类离线评测不自动加入正式章审流程。

## 评测与记录

离线盲测与实际用量命令见 [编辑能力](editorial.md)。变体预期保留在私有文件，评审只获得冻结正文样本，先冻结首读；原稿不是金标准，误报须独立裁决。修稿重新首读，确认原缺陷消失且没有新损失。

工程结果与原始度量见 [验收记录](../validation/results.md) 及 [metrics.json](../validation/metrics.json)。维护当前操作文档时保留历史记录的日期、版本和实验条件，不把后来通过的检查追写成早期结论。

连续性与宿主新增回归：test_execution_handoff、test_continuity_flow、test_host_authority。前两者验证真实CLI/事务边界与准确候选，后者验证签名对象、实际上下文与一次性消费；它们不证明某个真实宿主已完成OS权限隔离，也不证明独立模型不会漏报。
