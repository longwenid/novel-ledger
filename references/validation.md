# 验证

何时读：修改引擎、检查协议与材料成本，或设计真实长篇的文学及用量验收。

## 验证范围与结论依据

| 范围 | 使用的证据 | 能支持的结论 |
|---|---|---|
| 工程行为 | 临时新项目、合成回执、真实子进程、行为及依赖测试 | 提交、回滚、权限、版本与恢复符合协议 |
| 材料与存储 | 冻结记录字节、目录页、来源哈希、读取观测 | 来源保真、复用和读取量；字节不能直接换算计费 |
| 文学效果 | 连续完整正文、真实卷界、独立盲读与裁决 | 人物、因果、节奏和兑现的具体得失 |
| 宿主与费用 | 真实子 agent 会话、派工与提交记录、token/缓存及账单日志 | 模型历史隔离、子 agent 执行与真实费用 |

工程夹具不调用付费模型，明确标记为合成材料。语义判断沿 [创作与写审](craft.md) 的原文、问题、影响与修订范围进行，不用字段通过率、节点数量或源码行数替代文学质量。

## 工程检查

先按下表选择受影响的行为回归。跨模块规则、持久化结构或公共协议的广泛变更使用全量测试；依赖、材料选择或历史传输变化时另做度量。仅调整文档时，核对链接、示例和相关图源；若改写了操作流程，再运行对应行为回归。

在技能仓库根目录执行，按本次改动选用：

```bash
python3 validation/run_tests.py fast
python3 validation/run_tests.py full
python -m pytest tests/ -n auto          # 全量并行（装 pytest-xdist；用例各建临时项目，可安全并行）
python3 <skill-creator>/scripts/quick_validate.py ROOT
python3 validation/measure.py --out /path/to/metrics.json
```

`fast` 固定覆盖架构、端口替换、角色与首读隔离、有限预算、修订授权及端到端交付（含档位形状声明与 findings/批次规则守卫）；`full` 自动发现 tests/ 中全部测试。两种入口均在失败时返回非零状态，可供本机或 CI 调用；`--list` 仅列出案例，`-v` 显示逐项结果。全量回归优先用 pytest 并行入口（16 核实测 470 项约 87 秒，串行约 10 分钟；最慢的修订边界/叙事全流程驱动单条 15～25 秒，由多核吸收）。新增关键边界时维护快速组，新增测试始终由完整组自动收集。快速检查通过后，跨模块重构仍须完整回归；原 unittest discovery 命令继续可用。

`validation/anchor_check.py` 核对仓库内全部 markdown 锚点引用可解析（改标题或挪小节后运行）。quick_validate 属宿主自带工具，路径按本机实际安装替换；它是可选的附加校验，缺失时不影响上面的测试与测量。Windows 控制台默认 GBK：测试与 CLI 自身按 UTF-8 读写，但外部校验脚本可能仍按本地编码读文件，此时对全部命令加 `PYTHONUTF8=1`。

### 按改动类型选择验证

| 改动类型 | 必查行为 | 回归入口（tests/ 下） |
|---|---|---|
| 提交、约定与恢复 | 原子初始化、幂等、预检回滚、有限返修和准确版本认可；改约优先完成核验，字面规则跨激活与撤销保留；畸形回执、计划和评测清单不留下部分提交。 | test_runtime、test_output_repairs、test_alignment_profiles |
| 派工、身份与宿主 | compact 保留完整材料及已填表单；首读封印与原会话恢复，--after 拒绝未提交或旧回调；认领后故障释放租约，非文件交付在认领前拒绝。 | test_runtime、test_frozen_reading、test_host_ports |
| 模块依赖与端口 | 全作用域 import 白名单、无环与核心 I/O 禁令；用内存账本、替代交付、公开宿主能力和运行工厂实际完成用例。 | test_architecture、test_application_ports、test_domain_boundaries、test_presentation_boundaries、test_host_ports、test_cli_boundary |
| 存储与组合根 | 同根快照、未变哈希复用、损坏及跨区字段拒绝；文件回收只在提交后执行，回滚保留材料；真实 SQLite、CLI 重开与冻结交付重试。 | test_storage_boundaries、test_bootstrap、test_history |
| 开书、卷纲与叙事 | 逐门作者决定、近期覆盖、current/all 范围、跨卷续接、场景来源、覆盖树与完本兑现。 | test_opening、test_outlines、test_narrative、test_longform |
| 创作记忆与场景身份 | 理解、样本及反证绑定准确版本；原文失效与携带恢复，场景移动保留身份，阅读关联与重读转返修，拒绝回滚和显式启用。 | test_workbench |
| 历史修订与阅读影响 | 直接及传递依赖、连续区间输出、节点带动线路与保守扩大；表达/阅读不改事实，窄修核对后缀，扩大终点同步传播，改案后重新写审，重规划与人物重核不重复消耗正文额度。 | test_longform、test_revision_repairs、test_alignment_profiles、test_workbench |
| 自动回改与授权 | 创建分支前检查近期及闭卷边界，超界保留原稿与额度；准确哈希授权、来源过期拒绝、预检回滚与旧根审语义；追加章不提前冻结，缺范围旧关闭记录保守保护。 | test_revision_bounds |
| 编辑、页面与交付 | 成长重核、补丁与独立重审、有界补写、根预算和终审覆盖；模板随安装复制、异地运行、离线单文件及内容转义，准确快照交付。 | test_editorial、test_alignment_profiles、test_bookpage、test_bootstrap |
| 旧项目与冻结版本 | 基础/叙事/编辑夹具分别验证；清单、事件、阅读关联和旧计划按原版本解释；v2 及更早库拒绝且原文件不变，旧已接受开书板仍可选择。 | test_runtime、test_opening_legacy、test_creation_bounds、test_workbench |
| 技能、文档与测试入口 | 元信息、链接锚点、命令示例及当前操作说明一致；架构图源与派生物一致；快速组无重复且为完整组的子集，保留关键边界。 | [技能指令与路由验收](#技能指令与路由验收)、test_architecture、test_validation_runner |

表中的入口是定位起点，按实际调用关系补充关联回归；核验要求分别维护于 [运行](runtime.md)、[协议](protocol.md)、[叙事推进](narrative.md) 和 [编辑能力](editorial.md)。验证观察提交、拒绝、保留、恢复和交付等结果，避免只匹配文档措辞或实现细节。真实模型历史隔离仍需宿主另验收。

例如只改自动回改逻辑时，可先运行：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_revision_bounds.py' -v
```

文档检查重点包括等待与 --after、accepted 与正文通过的区别、超界方案落盘及授权入口。图表依赖未变时核对派生源码一致性即可；历史验收保留原条件，新增检查另行留档。

## 技能指令与路由验收

修改技能入口或专项指南时，先检查 frontmatter、UI 元信息、本地链接与锚点、表格和命令示例，再按下列场景核对读取顺序及实际行为。优先复用隔离临时项目中的现有行为测试，不为表格措辞添加断言。

| 代表请求或状态 | 应读入口 | 应观察到的行为 |
|---|---|---|
| “没有想法，帮我开一本书” | [逐门开书](opening.md#入口选择) | 从第一门开始，提交方案后等待作者，不自行选择或开始正文。 |
| “题材和书名已定，继续补齐” | [逐门开书](opening.md#入口选择) | 合法部分选择经 intake 登记；不重问已有决定，不绕过已展示门板。 |
| “继续这个已有项目” | [运行与恢复](runtime.md#主干循环默认执行路径) | 恢复同一任务及作者目标；有效认领等待，冻结首读沿原审稿会话继续。 |
| “审这一章”或盲审待解锁 | [创作与写审](craft.md)、当前冻结任务 | 完整正文先读，首读封印后解锁正式资料；不读取执笔自评或冒用新身份。 |
| “改旧章”或回改超界 | [修订影响分析](runtime.md#修订影响分析) | 先分析事实与阅读影响；保护正式稿，超界绑定准确方案授权。 |
| “交付已完成的内容” | [运行与恢复](runtime.md#阶段结束与交付) | 区分实际 coverage 与全书；完本先验收，导出失败只重试准确快照交付。 |
| “优化这个 skill”或仅讨论架构 | [架构](architecture.md)、本页 | 修改或分析技能工程，不创建小说项目或派创作任务。 |

上述工程测试验证引擎能否执行这些边界，不能证明模型一定会选对指南。验证技能实际使用时，另记录代表请求、实际读取的参考文件、行动及结果；若调用独立使用者，应只给请求与待验技能，避免把预期路线当成答案注入。没有完成这类试用时如实注明，不将元信息检查等同于模型行为验收。

## 材料与历史度量

记录模块、完整依赖图和必读完整记录字节。增加未引用未来节点时，必读材料不应无故增长，全设计仍可按哈希补读；连续依赖链与 20/100/500 章覆盖树另测，保留完整来源。

history_transport 使用独立存储夹具，500 章包含至少 150 万合成汉字。记录目录入口、原全量摘要/事件索引字节、首次构建与复用、实际事件页读取、无命中最坏扫描和最早章完整补读。行为测试覆盖损坏、冻结边界、分支共享前缀、承诺关联、原事件解释及补读量留痕；存储夹具不算已写审完本。

对照架构或流程时固定相同创作输入、模型和来源，计入首次正文前规划量、后续补纲/重规划、修订范围、实际读取量及新增场景材料。测量结果按条件报告，不将任务减少或分区拆分直接等同于全程收益。

真实长篇文学对照尚未完成，试写按下一节先做连续数十章预验收，再验证远距离回归与授权长篇目标。

## 真实长篇验收

在作者授权的独立小说项目中固定模型、题材、篇幅、写审条件和验证档位，保存引擎版本、作者约定及准确交付快照。百万字目标须实际写审至授权终点并通过 complete/deliver；短篇试跑只算预验收。验收分别记录：

- 连续性：人物/物品再次出现时的远期承诺、跨卷因果和揭示，抽检原文与事实事件是否一致；漏报和错误关联由独立裁决记录。
- 多线与呼吸：盲读连续完整章节及真实卷界，检查主线是否可感、支线的作用、暗线线索与揭示、高潮余波和静章变化；用原文说明得失，不以固定推进间隔、角色标签或张力分数当金标准。
- 效率：分别保存派工/补读字符量、宿主实际 token/缓存日志、失败调用、返修次数及人工干预；对照版本应固定相同来源和模型条件。没有计费日志则费用未知，不从字节换算费用。

人物对白样本库、主线间隔提醒与其他节奏辅助先在同条件盲评中验证收益及误报，再决定是否引入；不把尚未证实的建议直接变成拒绝规则。

## 评测与记录

离线盲测与实际用量命令见 [编辑能力](editorial.md)。变体预期保留在私有文件，评审只获得冻结正文样本，先冻结首读；原稿不是金标准，误报须独立裁决。修稿重新首读，确认原缺陷消失且没有新损失。

工程结果与原始度量见 [验收记录](../validation/results.md) 及 [metrics.json](../validation/metrics.json)。维护当前操作文档时保留历史记录的日期、版本和实验条件，不把后来通过的检查追写成早期结论。
