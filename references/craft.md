# 创作与自比

何时读：整理已有要求、卷纲、章纲、人物设计、执笔、自比与返修。按当前阶段读取相关小节；本页统一创作判断，字段和执行步骤见末尾协议索引。

## 适用范围与规则级别

- 作者约定：已明确的题材、视角、基调、风格、体量和限制约束当前创作。沿用已有要求，不因升级重新问表单；需要改变已生效约定时走改约流程。
- 流程要求：区分已成立事实、角色所知、读者已见、可修订作品理解与未来设计；遵守任务的来源、冻结材料、机械核算与版本核验要求。设计、档案和理解不能自行确立事实，原文证据不能改写。章纲是结算契约：声明的增量必须与正文实际写出的变化一致。
- 写作建议：本页的场景组织、语言和节奏指引用于判断实际作用。结合作者约定、体裁和上下文采用，不按固定句式、场景节拍或词语出现次数判定质量。

机械通过不证明文学成立。自比应说明具体依据，不能只填结论；校验范围见 [叙事推进](narrative.md)。

## 分阶段写作指引

### 开书与规划

先整理读者承诺与基调、叙述视角、体量、世界前提与限制、主角欲望底线、核心关系、推进与终局、母题与书名、文风。已有要求直接采用，真实缺口才给少量因果不同的选项。无外挂、生活流等限制自始生效，不强迫特殊机制，也不越过已选禁区。

世界设定应支持长期冲突，卷纲写清卷职责、弧线、关键转折、高潮与兑现物，并给出可核算的卷末终值。`exit_state` 描述卷末局面，其文字含义由创作者判断。`turns` 要改变后半卷的对抗走向，不用同义的“继续推进”凑数。长度、范围与字段见 [卷纲](narrative.md#卷纲)。

进入每一卷前设计该卷章纲：每章约 150 汉字 synopsis 交代本章发生的事、人物处境与阅读作用。行动、阻力、选择与后果可以跨章承接；静章可以让人物停在未消化的情绪或关系里，不必每章齐备一套流程、即时解决问题或固定留下悬念。正文的具体氛围和细节留到执笔。先按真实前态算清本章实际发生的资源、位置、知情、时钟、人物增量，再写 `enter`/`exit`；没有变化就明确为空，不为填栏目硬造变化。

### 人物与场景

人物与对白的声线纪律以 [文风](style.md) 为唯一源。成长从已写行动、已付代价和关系变化中判断；动机变化后核对章纲人物增量与声线依据，不凭档案补造经历，允许人物暂未理解自己的变化。

新人物首次登场时在章纲 `new_entities` 内联给出档案字段（id/kind/name/role/desire/limit/knowledge_boundary）；人物变化行给 `choice` 与 `cost`。场景与章纲全文读取必读 `chapter_outline`；`scene_context/2` 通过 `plan_record` 引用它，`plan_hash` 绑定同一版本，`inputs` 给准确前态；`scene_sources` 绑定前置场景的已提交版本。疑点按本任务 `recall` 补读，同一上下文可复用版本未变的已读材料。作者可用信息不自动成为角色所知或本章披露。

任务提供 creative_memory 时，完整读取相关解释、原文表达样本、反证及适用范围。理解可并存或受质疑，不为迁就旧解释重写人物；显式引用失效时补读原文或重新提交章纲。理解保存和阅读关联按 [叙事工作台](workbench.md) 的冻结协议执行。

按场景作用组织目标、阻碍、选择、代价与变化，规划中写清意图和展开依据；这些关系可以跨场承接，不要求每场重复一套节拍。静章可承担生活质感、关系变化、情绪余波、恢复或暗线铺垫。对白体现人物当时的立场与策略，静默场景可以没有对白。

### 执笔

用文件编辑工具从当前 `result.template.json` 起稿，先把候选可靠保存为 UTF-8 `result.json`，再运行任务提供的 `preflight`、`submit` 文件命令。正文也可先存独立 UTF-8 文件，再用 JSON 序列化读入 `data.prose`；单双引号、换行等交给序列化处理，避免将长正文嵌在 `python -c` 或 shell 引号中。首写可保存完整正文，后续引用已有文件、局部编辑有问题的段落或字段，不反复重贴全文。完整读取同次机械报告，按位置和字段一并处理当前可修项后复检；报告没有要求的成立内容保留，身份、租约、引擎版本问题交主控，不靠改稿或猜 session 解决。

首章依作者约定写出完整实稿并经作者认可定调；写作纪律以 [文风](style.md) 为唯一源，认可后 `style_anchor` 按现行机制登记首章样本，后续沿样本承接气质。默认 `style_guard=observe` 只记录形状变化，作者选 `strict` 才按 `style_window` 限制数值。显式 `dialogue_ratio` 与高重复检查仍生效；视角按作者约定和原文自比，代词数量仅作线索。

心理、氛围和停顿可承担人物理解、情绪余波、线索或节奏作用，取舍纪律见 [文风](style.md)。

篇幅不足通过增加事件解决：先检查缺失的行动、阻力、关系、体验或后果，用新的情节事件补足有效展开，不以描写、重复或对话注水；比喻与句段的取舍纪律见 [文风](style.md)。

章纲固定情节目标、状态变化、伏笔动作与结果，表达在这些边界内自由展开：人物可以说反话、避开问题或迟疑，叙述可停在主观体验上，只要实际发生的事与知情边界成立。`plant` 要有读者可见的承诺载体，`payoff` 要真正兑现，中途承接用 `hook_refs`。写完按 [漂移核算](narrative.md#执笔自比与引擎核算) 核对，偏差附原因和原文并返修本章；`drift_check` 交事实核账，`self_check` 补充文风执行与实际修订依据。声明了 `dialogue_ratio` 或 `notes` 时说明落实情况。

脚本可以处理排版、文件组装和统计，不能用固定段落模板批量生成正文，或插入章号、数字与无意义文字来打断重复匹配。lint 对仅数字变化的长模板同样给出返修项。actual、status 与 verdict 根据最终正文逐项判断，不能默认 actual=planned、统一填 kept/clean；引文须支持所声明的变化，不能只保证这句话存在。修重复要重写本章的实际行动、阻力、关系或后果，不以改变检测结果代替修稿。

工作台模式下可随回执交顶层 `understanding` 增量（新解释、原文样本、反证），由引擎在入库时更新作品理解；默认从人物行动、对白或场景切入，不另加独立日期或“第一日、第二日”式标签，也不把章首固定为时间播报。需要交代时间时，将相对时间、昼夜变化或期限自然融入场景。章号不等于天数，允许多章发生在同一天；内部累计时钟不必写成日期，不为验收强行过夜。作者明确要求日记体、编年体或日期标记时按约定执行。

### 人物与表达的真实感

落笔前抓住人物此刻想得到或避开的东西，以及他在谁面前会有所保留。一个人可以言不由衷、迟疑、迁怒或先顾眼前小事；这些反应应来自已经写出的处境，允许矛盾暂时留着。人物不必准确概括自己，也不必一场谈话就承认成长；叙述可贴近他的自我辩解与一闪而过的念头。

对白考虑说话对象、关系远近与当下目的。同一句拒绝，熟人和陌生人的说法会不同；可以直说、岔开、只答半句，也可以沉默。不要让所有人轮流把因果、设定和道理解释清楚，不以固定口头禅或刻意残句区别人物。心理描写和清楚的交代都有位置，不要求每句话都藏潜台词。

细节先问人物为何注意它、怎样使用它或故意不看它。生活经验藏在动作的便利与麻烦、物件的磨损、照顾人的习惯里；不按五感凑清单，也不靠堆品牌、方言和琐碎闲话证明生活感。比喻、长句、幽默或抒情沿用作者风格，看当前视角和语境能否承受，不统一改成短句口语。

结构化前后值与核验解释留在回执。正文写出支撑变化的过程和必要数量，人物按自己的目的说话。本次写作或返修内连读当前段落，检查哪一句是在替任务说明核账，局部修正具体失真处；成立的表达保留，不另起统一润色流程。

## 自比与细节依据

写作时用下面几项核对具体疑点。事实的逐项结论与原文依据交 `drift_check`；`self_check` 说明本章文风与实际修订，具体问题交代原文、影响和改法，无需把事实核账再抄一遍。

- 事实与因果：核对来源、知情边界、动机桥梁、选择后果和场景依赖。声明的 `reads`/`depends_on` 要与正文因果一致；涉及资源/位置/知情/人物的计划外变化以结构化前后值写入 `unplanned`；依赖或章纲本身确实不成立时保留候选、说明具体矛盾，交由作者决定是否改纲，不能自动重排。
- 人物与语言：结合人物处境、作者约定和上下文判断声线、心理、描述及重复是否有效，保留承担作用的表达。用本章具体话语或叙述说明人物为什么这样说、这样看，允许没有缺陷时不强找问题。机械报告区分观察与返修；数值相似不证明写得自然，代词出现也不证明实际视角切换。
- 时间与视角：`clock` 增量要与正文的时间表达一致；章号不等于天数。约定声明视角时，核对人称、可叙述范围及切换交代；合理切换本身不判错。
- 长范围承接：比较主支线承诺、远距离因果、动机转变、高潮与静章的作用、卷末与终局兑现。`hook_refs`/`reader_refs`/`history_refs` 指到的东西要真在正文里承接；本卷 `required` 的伏笔要在卷末前真的兑现。

这些是创作判断的依据，不另设评分或固定推进间隔。文风的机械代理指标见 [叙事推进](narrative.md#文风)。

## 修订原则

后章与已验收前文冲突时，先检查能否修正当前章的行动、知情或表达；确有前文缺陷才给出其原文证据、影响和目标章。历史修订由作者明确要求发起，先做影响分析，超出自动范围时保存方案并等待准确授权，见 [运行](runtime.md#修订影响分析)。不能仅因后章难写就把成立前文推翻。

返修先读完整基稿、引擎拒绝的漂移项或 lint 命中、以及前态，确定问题实际影响的范围；当前正文返修按原固定章纲重写；作者明确授权改纲后，才按新章纲改写。交付可用当前任务支持的全文、版本补丁或原文复用。程序合成完整稿后重新执行同一套机械核算、字数区间、lint 与字面检查；旧稿通过不能替代新稿校验。

历史修订可先做 revision-impact：表达修订保持事实投影不变；阅读变化声明 `reading_changes`；语义修订沿事实与场景依赖确定修改范围，依赖不全时保守扩大。受影响章的章纲由 `chapter_outline` 重排（payload 带 `repair=True` 与偏差清单），受影响的连续区间按动作重写，区间外后缀核对前态并重放事实后携带，原正式稿一直保留。分析不代替写作判断，改纲也不能掩盖实际缺陷。额度、版本和后缀核验按当前任务执行。
