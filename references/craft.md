# 创作与自比

何时读：整理已有要求、卷纲、章纲、人物设计、执笔、自比与返修。按当前阶段读取相关小节；本页统一创作判断，字段和执行步骤见末尾协议索引。

## 适用范围与规则级别

- 作者约定：已明确的题材、视角、基调、风格、体量和限制约束当前创作。沿用已有要求，不因升级重新问表单；需要改变已生效约定时走改约流程。
- 流程要求：区分已成立事实、角色所知、读者已见、可修订作品理解与未来设计；遵守任务的来源、冻结材料、机械核算与版本核验要求。设计、档案和理解不能自行确立事实，原文证据不能改写。章纲是结算契约：声明的增量必须与正文实际写出的变化一致。
- 写作建议：本页的场景组织与自比问题用于判断实际作用；语言、节奏和声线取舍由 [文风](style.md) 与生效档案维护。结合作者约定、体裁和上下文采用，不按固定句式、场景节拍或词语出现次数判定质量。

机械通过不证明文学成立。自比应说明具体依据，不能只填结论；校验范围见 [叙事推进](narrative.md)。

## 分阶段写作指引

### 开书与规划

先整理读者承诺与基调、叙述视角、体量、世界前提与限制、主角欲望底线、核心关系、推进与终局、母题与书名、文风。已有要求直接采用，真实缺口才给少量因果不同的选项。无外挂、生活流等限制自始生效，不强迫特殊机制，也不越过已选禁区。

开篇节奏是设计期约束，不等到执笔再补救：开卷首章立主角处境、代价与可见钩子，开卷前几章（通常 3～5 章）内出现第一个可感知的兑现或明确承诺，让期待感尽早落地；开篇白描与设定交代不长期压住人物与冲突，能力来源、代价与保密动机这类设定信息分次给出、不在一段灌完。此为方向性提示（无机械判据、不设数值公式），随卷纲与章纲派工携带，供设计自审；章级对应物见 [结构纪律](narrative.md#结构纪律)。

世界设定应支持长期冲突，卷纲写清卷职责、弧线、关键转折、高潮与兑现物，并给出可核算的卷末终值。`exit_state` 描述卷末局面，其文字含义由创作者判断。`turns` 要改变后半卷的对抗走向，不用同义的“继续推进”凑数。长度、范围与字段见 [卷纲](narrative.md#卷纲)。

[卷纲设计蓝图](volume-blueprint.md)当前是 v1.2 **待作者确认稿**：选择与派工机制尚未接入，本次修订未复验外部语料，不把引文存在等同于规律成立——**确认前不供写作项目使用**，本段其余内容只在作者确认并选定蓝图后生效。已选定后可按其适用条目展开设计：蓝图负责样本与设计建议，[卷纲蓝图对接](volume-blueprint-bridge.md) 负责字段映射，执行形状与校验统一见 [叙事推进](narrative.md#卷纲)；先判断首卷、终卷、单卷与题材适用性，默认建议可说明偏离，参考条目按需采用，不据此自动返工。未选定（含未确认）时维持 [五条方向性结构纪律](narrative.md#结构纪律)。注意与引擎的「结构蓝图」（structure blueprint，`blueprint` 命令绑定，见 [创意工具箱](hatch.md#结构蓝图目录)）是两套系统：前者是设计参考文档，后者是引擎功能，两者可各自独立选定。

进入每一卷前设计该卷章纲：每章约 150 汉字 synopsis 交代本章发生的事、人物处境与阅读作用。行动、阻力、选择与后果可以跨章承接；静章可停在未消化的情绪或关系里，不必每章齐备一套流程、即时解决问题或固定留下悬念。正文的具体氛围和细节留到执笔；先算真实增量，再写 enter／exit，没有变化就明确为空。

结构表达按 [章纲协议](narrative.md#章纲) 组织：beats 是读者阅读顺序，可含倒叙、插叙和双线交替，事件时间与场景依赖分别处理；role 说明本章作用，相邻多章可以共享调查、战斗或余波等职责，观察实际压力与后果，不轮换标签。两者不定数量、不作正文模板。plot.threads 表达各线如何相互影响；所需世界记录用 world_refs 点名，出场者与直接关联随任务筛选，其他设定按冻结来源补读。

揭示设计区分“本章呈现什么”和“暂时保留什么”：实际线索、误导或确认进 disclosures，note 解释这次披露的节奏；仅暂不揭示的意图放在现有 pacing 或 scenes.intent，不为一条备注制造认知变化。外层身份与内层动机等可分别判断的命题用独立 topic，避免用同一条备注承载两个认知状态。观察连续章节中期待如何累积、转换与兑现，不要求每章揭密。

### 卷纲因果设计

卷纲先回答“人物如何把局面推到这里”，再填写字段。以下方法适用于所有项目，未选定与已选定设计蓝图皆以此为设计入口（与蓝图 §用法及对接文档口径一致）；蓝图的 49 条建议是按需工具，不要求每卷逐条作答或另交推演报告。当前任务已有的 contract、world_model、opening_choices/opening_basis（若有）、previous_volume_outline（若有）和 hooks 是来源；不另建“十三门副本”或第二套世界状态。

1. **核心问题**：主角本卷具体想得到或保住什么，什么局面让他现在必须行动？从阅读承诺、核心设想、来历、欲望底线及上卷后果中选本卷真正相关的矛盾。先确定问题，不先贴“扩张卷”等类型标签。
2. **双方行动与阻力**：主角打算怎样解决；对手自身要什么，会主动采取什么行动；双方利用哪些规则、资源、组织与关系？世界的历史遗留和制度通过这些行动产生压力，避免只作背景。核心优势按已选来源、代价和上限使用；无机制、无外挂的决定自始有效。
3. **关键选择与代价**：主角在哪个节点无法两全，选择了什么、放弃什么，谁会因此反击或改变立场？转折来自行动与回应，数量和落点按故事需要确定。人物变化也可以源于成功、责任、亲密、长期实践等，不封闭为生死／失去／真相三类。
4. **不可逆后果**：前述选择如何改变利益、关系、规则理解或未来选项，让故事不能原样继续？静卷可以积累关系和认知后果，不强造大战、升级或换图。撤去关键事件后，如果后续仍可原样发生，就检查它是否承担了所声称的作用。
5. **兑现与收束**：本卷回应哪些读者期待，前卷到期承诺和阶段兑现如何落地？按作者选定的兑现方式、期限与终局主题安排；非终卷留下可继续承担的后果，终卷／单卷检查结局。高潮形式服务人物选择和解决方式，不按卷型固定配宴席、战役或摊牌。

**最后映射与核算**：用 purpose 概括职责，arc 展开整条因果，turns 摘出实际改变走向的事件，climax 写解决与兑现，exit_state 写结果与后续条件；nodes／threads 是对已成立事件弧和线路的组织，hooks 记录具体承诺，六轴终值与 clock 核算其结果。不能先独立填满状态终值，再为对账倒造事件。解释写入已有叙述字段，必要时在关键因果处指明世界记录 id，不新增必填追溯字段。

### 十三门、世界与卷纲的承接

下表说明各门决定怎样被使用；门序和字段归属的权威仍是 creation.GATES 与 contracts.CONTRACT_FIELDS，不在此重定义 schema。世界与完整约定同任务提交，约定激活时机见 [系统执行](opening.md#系统执行)，初次激活按门选择逐字对齐；后续已授权改约以当前生效约定为准，原选择保留出处。直接导入约定没有十三门材料时，按实际约定与世界设计，不补造选择记录。

| 门 | 世界／约定承接 | 卷纲如何使用 |
|---|---|---|
| 题材与阅读承诺 | genre、reader_promise、tone | 决定本卷要给读者的体验与期待，影响核心问题和兑现 |
| 核心设想与世界命题 | core_premise 的 novelty／first_cause 等 | 决定冲突为何持续产生，避免每卷另造起因 |
| 体量与分卷 | 档位、卷界、章幅与字量 | 决定本卷展开尺度；篇幅预算不替代故事因果 |
| 世界架构 | world_premise、架构、规则、位阶与资源在模型落地 | 从历史遗留、制度限制与分配矛盾取实际阻力 |
| 格局路径与终局视野 | world_scale／world_ladder 及世界同名记录 | 确定本卷舞台和进入条件，升格带来什么新规则与代价 |
| 写作视角 | voice、pov、style_traits | 约束跟随者、知情范围与换人方式；文风另按档案，读者与角色所知分别安排 |
| 主角来历与世界联系 | protagonist_origin | 让经验、旧关系与来历代价参与本卷行动，不重复介绍身世 |
| 核心优势与成长线 | core_edge 的来源、成长、代价、上限 | 决定解决手段及其边界；不自动引入金手指 |
| 主角处境与底线 | protagonist_setup、世界人物档案与初始实体 | 提供欲望、无法两全的选择及不能轻易跨过的底线 |
| 多方对抗与持续冲突 | opposition、story_engine，世界各方利益 | 给对手独立目标与主动行动，形成持续压力和回应 |
| 人物关系与立场 | relationships、世界人物与组织关联 | 把帮助、依赖、亏欠与背叛风险变成行动条件与关系后果 |
| 阶段兑现与终局回应 | payoff_plan、promise_anchor、ending、theme | 安排本卷兑现与全书终局的关系，处理已选期限 |
| 书名 | title | 核对本卷是否持续提供书名许诺的核心体验，不要求机械复述标题 |

**三种绑定各有边界**：选择版本与完整材料经冻结输入绑定；世界声明、约定逐字对齐及阶梯／资源／实体引用由现有领域规则核对；“本卷是否真正用世界矛盾推动人物选择、是否兑现了承诺”属于创作判断，在原任务内自查并由卷纲作者认可门核看。材料齐全或测试通过不证明第三种绑定已经成立。

### 人物与场景

核心人物的小传应能解释其当下选择：过往如何形成欲望和底线，矛盾怎样在压力下暴露，关系带来何种牵制，行动与说话方式怎样体现这些因素。群像按各核心行动者分别推演，不给全员套同一段背景；普通配角只展开本次行动需要的依据。字段统一见 [人物档案](editorial.md#人物档案)，不在正文轮流展示四栏，也不把初始设定锁成永不成长的性格。

人物与对白的声线纪律以 [文风](style.md) 为唯一源。成长从已写行动、已付代价和关系变化中判断；动机变化后核对章纲人物增量与声线依据，不凭档案补造经历，允许人物暂未理解自己的变化。

作者选双主角或群像时，人物与关系设计分别交代核心人物的目标及牵制；卷纲推演各自行动如何相互改变局面，章纲在需要处落实当前跟随者、行动、选择与后果。可用既有人物／关系、arc、threads、scenes 和 style.pov 承接，不新增报告或固定出场配额，不把群像退化成“主角做事、配角轮流点评”。全知叙述也须区分叙述者揭示、人物所知与读者已见。

新人物首次登场时在章纲 `new_entities` 内联给出档案字段（id/kind/name/role/desire/limit/knowledge_boundary）；人物变化行给 `choice` 与 `cost`。场景与章纲全文读取必读 `chapter_outline`；`scene_context`（冻结的场景输入，写法见 [协议](protocol.md)）通过 `plan_record` 引用它，`plan_hash` 绑定同一版本，`inputs` 给准确前态；`scene_sources` 绑定前置场景的已提交版本。疑点按本任务 `recall` 补读，同一上下文可复用版本未变的已读材料。作者可用信息不自动成为角色所知或本章披露。

任务提供 creative_memory 时，完整读取相关解释、原文表达样本、反证及适用范围。理解可并存或受质疑，不为迁就旧解释重写人物；显式引用失效时补读原文或重新提交章纲。理解保存和阅读关联按 [叙事工作台](workbench.md) 的冻结协议执行。

按场景作用组织目标、阻碍、选择、代价与变化，规划中写清意图和展开依据；这些关系可以跨场承接，不要求每场重复一套节拍。分场时对话场/动作场/日常场等类型写进 `scenes` 的 `label`/`intent`（方向自定，不强制每章分场）；人物间的压力先在场景意图和行动中呈现；形成实际关系状态变化时再申报 `relations` 增量，不为临时情绪制造稳定关系变化。静章可承担生活质感、关系变化、情绪余波、恢复或暗线铺垫。对白体现人物当时的立场与策略，静默场景可以没有对白。

### 执笔

用文件编辑工具从当前 `result.template.json` 起稿，先把候选可靠保存为 UTF-8 `result.json`，再运行任务提供的 `preflight`、`submit` 文件命令。正文也可先存独立 UTF-8 文件，再用 JSON 序列化读入 `data.prose`；单双引号、换行等交给序列化处理，避免将长正文嵌在 `python -c` 或 shell 引号中。首写可保存完整正文，后续引用已有文件、局部编辑有问题的段落或字段，不反复重贴全文。完整读取同次机械报告，按位置和字段一并处理当前可修项后复检；报告没有要求的成立内容保留，身份、租约、引擎版本问题交主控，不靠改稿或猜 session 解决。

首章依作者约定写出完整实稿并经作者认可定调；写作纪律以 [文风](style.md) 为唯一源，认可后 `style_anchor` 按现行机制登记首章样本，后续沿样本承接气质。默认 `style_guard=observe` 只记录形状变化，作者选 `strict` 才按 `style_window` 限制数值。显式 `dialogue_ratio` 与高重复检查仍生效；视角按作者约定和原文自比，代词数量仅作线索。

心理、氛围和停顿可承担人物理解、情绪余波、线索或节奏作用，取舍纪律见 [文风](style.md)。

篇幅不足先检查章纲内尚未充分展开的行动、阻力、关系、体验或后果；在固定事实边界内补足有效展开，不用重复和无意义文字凑数。表达取舍见 [文风](style.md)。

章纲固定情节目标、状态变化、伏笔动作与结果，表达在这些边界内自由展开：人物可以说反话、避开问题或迟疑，叙述可停在主观体验上，只要实际发生的事与知情边界成立。`plant` 要有读者可见的承诺载体，`payoff` 要真正兑现，中途承接用 `hook_refs`。写完按 [漂移核算](narrative.md#执笔自比与引擎核算) 核对，偏差附原因和原文并返修本章；`drift_check` 交事实核账，`self_check` 补充文风执行与实际修订依据。声明了 `dialogue_ratio` 或 `notes` 时说明落实情况。

脚本可以处理排版、文件组装和统计，不能用固定段落模板批量生成正文，或插入章号、数字与无意义文字来打断重复匹配。lint 对仅数字变化的长模板同样给出返修项。actual、status 与 verdict 根据最终正文逐项判断，不能默认 actual=planned、统一填 kept/clean；引文须支持所声明的变化，不能只保证这句话存在。修重复要重写本章的实际行动、阻力、关系或后果，不以改变检测结果代替修稿。

工作台模式可随回执交顶层 `understanding` 增量（新解释、原文样本、反证），入库时更新作品理解。章号不等于天数，允许多章发生在同一天；clock 核对实际时间变化，不要求为验收过夜或添加日期标签。章首与时间表达由作者约定及生效档案决定。

### 人物与表达的真实感

本节用于诊断当前段落，不另定声线要求；表达取舍按 [文风](style.md)。核对人物此刻想得到或避开什么，其行动、对白和注意到的细节是否得到处境、关系及已知信息的支持。人物可以迟疑、矛盾或暂未理解自己；口癖可以承担辨人作用，但不能代替行动与关系依据。

发现具体问题时，说明原文、影响与局部改法；结构化前后值和核验解释留在回执。成立的表达保留，不因诊断另开统一润色流程。

## 自比与细节依据

写作时用下面几项核对具体疑点。事实的逐项结论与原文依据交 `drift_check`；`self_check` 说明本章文风与实际修订，具体问题交代原文、影响和改法，无需把事实核账再抄一遍。

- 阅读收获：在原有 self_check 中结合具体正文说明“读者本章得到了什么，哪种期待被回应、加深或改变”。可以是情节、情绪、关系、人物理解或生活体验，静章同样可以成立。连读相邻章检查重复、空转与承接；发现具体问题才局部修正，不新增报告、评分或独立审核任务。
- 事实与因果：核对来源、知情边界、动机桥梁、选择后果和场景依赖。声明的 `reads`/`depends_on` 要与正文因果一致；涉及资源/位置/知情/人物的计划外变化以结构化前后值写入 `unplanned`；依赖或章纲本身确实不成立时保留候选、说明具体矛盾，交由作者决定是否改纲，不能自动重排。
- 人物与语言：结合人物处境、作者约定和上下文判断声线、心理、描述及重复是否有效，保留承担作用的表达。用本章具体话语或叙述说明人物为什么这样说、这样看，允许没有缺陷时不强找问题。机械报告区分观察与返修；数值相似不证明写得自然，代词出现也不证明实际视角切换。
- 时间与视角：`clock` 增量要与正文的时间表达一致；章号不等于天数。约定声明视角时，核对人称、可叙述范围及切换交代；合理切换本身不判错。
- 长范围承接：比较主支线承诺、远距离因果、动机转变、高潮与静章的作用、卷末与终局兑现。`hook_refs`/`reader_refs`/`history_refs` 指到的东西要真在正文里承接；本卷 `required` 的伏笔要在卷末前真的兑现。

这些是创作判断的依据，不另设评分或固定推进间隔。文风的机械代理指标见 [叙事推进](narrative.md#文风)。

## 修订原则

后章与已验收前文冲突时，先检查能否修正当前章的行动、知情或表达；确有前文缺陷才给出其原文证据、影响和目标章。历史修订由作者明确要求发起，先做影响分析，超出自动范围时保存方案并等待准确授权，见 [运行](runtime.md#修订影响分析)。不能仅因后章难写就把成立前文推翻。

返修先读完整基稿、引擎拒绝的漂移项或 lint 命中、以及前态，确定问题实际影响的范围；当前正文返修按原固定章纲重写；作者明确授权改纲后，才按新章纲改写。交付可用当前任务支持的全文、版本补丁或原文复用。程序合成完整稿后重新执行同一套机械核算、字数区间、lint 与字面检查；旧稿通过不能替代新稿校验。

历史修订可先做 revision-impact：表达修订保持事实投影不变；阅读变化声明 `reading_changes`；语义修订沿事实与场景依赖确定修改范围，依赖不全时保守扩大。受影响章的章纲由 `chapter_outline` 重排（payload 带 `repair=True` 与偏差清单），受影响的连续区间按动作重写，区间外后缀核对前态并重放事实后携带，原正式稿一直保留。分析不代替写作判断，改纲也不能掩盖实际缺陷。额度、版本和后缀核验按当前任务执行。
